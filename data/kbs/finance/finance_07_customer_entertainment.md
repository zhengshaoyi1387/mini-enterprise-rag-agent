# 客户招待与商务费用规范

> 知识库：finance。本文档用于企业内部 Agent 演示，包含制度口径、流程、边界条件、FAQ 和可引用条款。

## 适用范围

客户招待包括客户拜访餐饮、商务礼品、会议活动和必要交通安排。费用必须与真实业务活动相关。

## 事前审批

客户招待应提前说明客户名称、参与人员、业务目的、预算和预期结果。高额招待必须事前审批。

## 费用标准

普通客户餐饮应遵循节约原则，不得铺张浪费。礼品应符合合规要求，不得向客户个人提供高价值或现金等价物。

## 报销材料

需提供发票、消费清单、参与人、客户名称和业务说明。缺少业务说明的招待费用可能被退回。

## 合规红线

不得以招待名义进行商业贿赂、利益输送或规避客户采购合规要求。


## 扩展说明

### 适用对象
本文主要适用于：员工、部门负责人、财务和采购相关人员。当员工不确定是否适用时，应结合自己的岗位、部门、角色权限和业务场景判断，必要时联系对应制度 owner。

### 典型使用场景
该文档适合用于处理：费用报销、预算、采购、合同付款和税务合规场景。在企业 Agent 中，用户可以用自然语言提问，系统会根据角色权限选择可访问知识库，再检索相关章节作为回答依据。

### 执行原则
所有费用都应满足真实性、合理性、业务相关性和审批完整性。 如果 Agent 回答和制度原文存在差异，应以制度原文和正式审批结果为准。Agent 返回的来源文档、章节路径和 trace_id 可用于排查回答依据。

### 操作建议
1. 查询制度时尽量说明身份、场景、对象和期望结果，例如“我是 finance 角色，想确认差旅住宿是否超标”。
2. 涉及审批、金额、权限、客户承诺或个人信息时，不要只依赖一句回答，应查看引用来源。
3. 如果问题跨多个知识库，应让管理员或具备对应权限的角色查询，避免因权限不足导致证据不完整。
4. 如果没有找到相关内容，应反馈给知识库 owner 补充文档，而不是让 Agent 编造结论。

### 风险与例外
- 制度可能存在版本更新，旧文档应归档或标记失效。
- 涉及敏感信息时，用户只能访问自己角色允许的知识库。
- 高风险动作不能由 Agent 直接执行，应进入人工确认或正式审批流程。
- 对外承诺、财务结论、人事结论和安全处置结论必须由对应负责人确认。

### FAQ
**问：Agent 的回答能不能作为最终结论？** 不能。Agent 是知识检索和草稿生成助手，最终结论以制度原文、审批系统和负责人确认为准。

**问：为什么我查不到某些内容？** 可能是知识库没有收录，也可能是当前角色没有权限访问对应知识库。

**问：发现文档错误怎么办？** 应记录文档名、问题描述和 trace_id，反馈给知识库 owner 或管理员。
