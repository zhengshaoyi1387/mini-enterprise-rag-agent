# 知识库 Owner 职责说明

> 知识库：public。本文用于扩充企业知识库数据，便于检索、权限和 Agent 演示。

## Owner 职责

知识库 owner 负责内容准确性、更新频率、权限边界和问题反馈处理。

## 更新频率

公共制度至少季度复核一次；产品文档随版本更新；故障预案在重大事件后复盘更新。

## 反馈处理

用户反馈文档错误时，owner 应判断是否需要修订，并在变更摘要中说明。

## 权限协作

如果文档涉及受限信息，owner 应与管理员确认知识库权限，不建议在公共库中存放敏感内容。


## 扩展说明

### 适用对象
本文主要适用于：全体员工。当员工不确定是否适用时，应结合自己的岗位、部门、角色权限和业务场景判断，必要时联系对应制度 owner。

### 典型使用场景
该文档适合用于处理：公共制度、协作流程和通用办公场景。在企业 Agent 中，用户可以用自然语言提问，系统会根据角色权限选择可访问知识库，再检索相关章节作为回答依据。

### 执行原则
员工应优先查看知识库原文，再结合直属负责人或文档 owner 的最新说明执行。 如果 Agent 回答和制度原文存在差异，应以制度原文和正式审批结果为准。Agent 返回的来源文档、章节路径和 trace_id 可用于排查回答依据。

### 操作建议
1. 查询制度时尽量说明身份、场景、对象和期望结果，例如“我是 finance 角色，想确认差旅住宿是否超标”。
2. 涉及审批、金额、权限、客户承诺或个人信息时，不要只依赖一句回答，应查看引用来源。
3. 如果问题跨多个知识库，应让管理员或具备对应权限的角色查询，避免因权限不足导致证据不完整。
4. 如果没有找到相关内容，应反馈给知识库 owner 补充文档，而不是让 Agent 编造结论。

### 风险与例外
- 制度可能存在版本更新，旧文档应归档或标记失效。
- 涉及敏感信息时，用户只能访问自己角色允许的知识库。
- 高风险动作不能由 Agent 直接执行，应进入人工确认或正式审批流程。
- 对外承诺、财务结论、人事结论和安全处置结论必须由对应负责人确认。

### FAQ
**问：Agent 的回答能不能作为最终结论？** 不能。Agent 是知识检索和草稿生成助手，最终结论以制度原文、审批系统和负责人确认为准。

**问：为什么我查不到某些内容？** 可能是知识库没有收录，也可能是当前角色没有权限访问对应知识库。

**问：发现文档错误怎么办？** 应记录文档名、问题描述和 trace_id，反馈给知识库 owner 或管理员。
